- **HOW**: Claude Code를 어떻게 활용했는가

- 프레젠테이션 내용이 어떻게 변화했는가

- 목차 구조가 어떻게 개선되었는가

**핵심 차이점:**
- Development log = "어떻게 작업했는가" (프로세스)

## 작업 원칙 (Working Principles)



### 2. 점진적 개선 (Iterative Refinement)
- 완벽한 초안을 목표로 하지 않음
- 빠른 프로토타입 → 피드백 → 개선
- 각 사이클에서 핵심 문제 하나씩 해결

### 3. 명확한 피드백 (Clear Feedback)
좋은 피드백 예시:
> "이거 진짜 개구리다. PPT 화면 생각말고 스크립트만 생각해."

- **무엇이 문제인지** 명시: PPT 중심 접근
- **왜 문제인지** 설명: 발표 스크립트 목차여야 함
- **어떻게 바꿀지** 방향: 말로만 하는 것처럼

### 4. 유연한 구조 (Flexible Structure)
- 초기 계획에 집착하지 않음
- 더 좋은 아이디어가 나오면 과감히 재구성
- "프리즈"하기 전까지는 계속 개선

## Development Log 작성 가이드

### 📝 왜 사례 기반 패턴이 중요한가

Development log의 진짜 가치는 **"이렇게 했더니 안 돼서 → 이렇게 하니 잘되더라"** 패턴입니다.

```
추상적 설명: "효율적인 작업이 중요합니다" ❌
구체적 사례: "완성된 슬라이드를 만들었더니 재사용이 안 됐다.
             작은 요소들로 나누니 레고처럼 조립 가능했다." ✅
```

**이유:**
- 다른 사람이 똑같은 실수 반복 안 함
- "아, 나도 이렇게 하면 되겠구나" 즉시 이해
- 발표 자료로 활용 시 청중 공감 ↑

### 📚 포함하면 좋은 패턴 유형

#### 1. 피봇 사례 (방향 전환)
```
실패: "GTO vs Exploit 슬라이드 1개 만들어줘"
     → 한 번 쓰고 버리는 이미지

피드백: "presentation page 1개를 그려주는구나. 그건 여기 역할이 아니야"

성공: 25개 재사용 가능한 SVG 컴포넌트
     → 레고 블록처럼 조립
```

#### 2. 도구 활용 실전 팁
```
상황: 프레젠테이션용 이미지 25개 필요

비효율: 하나씩 순차적으로 생성 요청

효율: "독립적이니까 병렬로 만들어줘"
     → Write 도구로 동시에 여러 파일 생성
     → 일관된 디자인 패턴 적용
```

#### 3. 세션 관리
```
문제: 대화가 길어져서 컨텍스트 부족

해결: Claude가 자동으로 요약 → 새 세션 시작

핵심: "파일은 영원하고, 대화는 일시적이다"
     → 중요한 결정은 CLAUDE.md, outline.md에 기록
     → 세션 바뀌어도 파일 읽고 맥락 이해
```

#### 4. 효과적인 피드백
```
모호함: "이거 좀 이상해"
     → Claude가 무엇을 고쳐야 할지 모름

명확함: "중앙에 큰 텍스트 이거 진짜 개구리다.
        PPT 화면 생각말고 스크립트만 생각해"
     → 무엇이 문제인지 + 왜 + 어떻게 바꿀지
```

#### 5. Progressive Icon Animation (Session 6)
```
문제: 텍스트 중심 슬라이드 → "스크립트 덩어리"

해결: 재사용 가능한 CSS Pattern 확립
     .progressive-icon {
       opacity: 0.25;          /* dim */
       filter: grayscale(80%);
       transform: scale(0.95);
     }
     .current-fragment {
       opacity: 1;             /* bright */
       filter: grayscale(0%);
       transform: scale(1.05);
     }

효과: "PT 만드는 사람들에게 강요할 수 있게"
     → Class만 추가하면 자동으로 일관된 애니메이션
```

**핵심**: 재사용 가능한 패턴으로 디자인 일관성 강제

#### 6. Issue-Driven Development (Session 6)
```
상황: 다른 세션이 CSS 템플릿 작업 중

충돌 방지 전략:
1. 개선점 발견 → 즉시 구현 (X)
2. 개선점 발견 → GitHub Issue 생성 (O)
   - 현재 상태 (파일, 라인 번호)
   - 개선 방향
   - 구현 방법
   - 우선순위 (High/Medium/Low)

결과: 16개 이슈 생성
     → 다른 세션이 pick 가능
     → 병렬 작업 충돌 제로
```

**교훈**: 코드 작성 전 Issue로 명세화 → 조율 용이
